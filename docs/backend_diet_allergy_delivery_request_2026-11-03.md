# 식단 알레르기 전달 관련 Backend 수정 요청

## 1. 최종 적용 방향

식단 생성은 범용 `/chat`이 아닌 식단 전용 API로 전환해 주세요.

| 기능 | AI Server API |
|---|---|
| 주간 식단 생성 | `POST /recommend/diet` |
| 한 끼 재추천 | `POST /recommend/diet/replace-meal` |
| 레시피 조회 | `POST /recommend/diet/recipe` |
| 일반 대화 | `POST /chat` |

`/chat`은 알레르기 파생 식품 검사와 식단 응답 형식을 강제하지 않으므로 최종 식단 생성 경로로 사용하지 않습니다.

## 2. 전환 전 임시 조치

기존 일간 식단 `/chat` 경로를 당분간 유지해야 한다면 `question` 내부 JSON에 다음 필드를 포함해 주세요.

```json
{
  "food_allergens": ["우유", "대두"]
}
```

이때 다음 정책을 유지해 주세요.

- 사용자 ID, 이름, 이메일 등 개인정보는 전달하지 않습니다.
- 알레르기명만 전달합니다.
- 기존 `conflicts_allergy()` 사후 검사를 제거하지 않습니다.
- 우유→요거트·치즈·버터, 대두→두부·콩·된장 같은 파생 식품도 검사합니다.
- 알레르기 충돌 결과는 저장하지 않습니다.
- 위반 결과를 임의의 다른 음식으로 조용히 교체하지 않습니다.

## 3. 수정 대상

### `backend/app/diet_ai.py`

- `generate_ai_meals()` 요청 데이터에 `food_allergens`를 추가합니다.
- 기존 `allergy_names`를 공백 제거·중복 제거해 사용합니다.
- 알레르기 사후 검사를 유지합니다.
- 일일 생성과 한 끼 재추천에 동일하게 적용합니다.

### `backend/app/diet_refresh.py`

- 자동 갱신 시 조회한 사용자 알레르기가 `generate_ai_meals()`까지 전달되는지 확인합니다.
- 사용자별 동시 요청에서 알레르기 값이 섞이지 않도록 검증합니다.

### `backend/app/main.py`

- 기존 일간 식단 API가 현재 Frontend 또는 Cron에서 실제 사용되는지 확인합니다.
- 주간 식단으로 전환할 경우 기존 일간 생성 경로의 비활성화 계획을 정합니다.
- 알레르기명 해석 실패를 빈 목록으로 조용히 처리하지 않습니다.

### `backend/app/chat_model.py`

- `user_info`에 사용자 개인정보 전체를 넣지 않습니다.
- 임시 경로에서는 `diet_ai.py`가 만든 비식별 JSON만 `question`으로 전달합니다.
- 식단 전용 API 전환 후 식단 생성에서 `/chat`을 호출하지 않습니다.

## 4. Backend 보관 정책 확인 요청

다음 항목의 보관 및 삭제 정책을 정해 주세요.

| 데이터 | 권장 정책 |
|---|---|
| 사용자 프로필 알레르기 | 사용자가 수정·삭제하거나 계정 탈퇴 시까지 |
| AI 요청용 알레르기 데이터 | 요청 처리 중에만 사용 |
| AI 요청·응답 원문 | DB와 운영 로그에 저장하지 않음 |
| 주간 식단 `request_context.food_allergens` | 주간 식단 보관 기간과 동일하게 관리 |
| 오류 로그 | 실제 알레르기명 대신 개수와 충돌 여부만 기록 |

현재 주간 식단 `request_context`에 저장되는 알레르기 snapshot에는 명시적인 TTL이 확인되지 않았습니다. 주간 식단 삭제 또는 만료 시 함께 삭제되도록 확인해 주세요.

## 5. 필수 테스트

- 사용자 알레르기가 AI 요청에 포함되는지
- 알레르기가 없으면 `food_allergens: []`로 전달되는지
- 우유 알레르기에서 요거트·치즈·버터가 거부되는지
- 대두 알레르기에서 두부·콩·된장이 거부되는지
- 알레르기 위반 결과가 저장되지 않는지
- 일일 생성·자동 갱신·한 끼 재추천에 같은 정책이 적용되는지
- 주간 식단의 기존 `food_allergens` 전달이 유지되는지
- 운영 로그에 사용자 식별정보와 실제 알레르기명이 남지 않는지

## 6. 완료 기준

- [ ] 기존 일간 식단 요청에 실제 `food_allergens`가 전달됩니다.
- [ ] Backend의 파생 알레르기 검사가 유지됩니다.
- [ ] 알레르기 위반 결과가 저장되지 않습니다.
- [ ] 개인정보가 AI 요청과 운영 로그에 포함되지 않습니다.
- [ ] 주간 식단 전용 API 전환 계획이 확정됩니다.
- [ ] 식단 및 알레르기 snapshot의 보관·삭제 기간이 확정됩니다.
