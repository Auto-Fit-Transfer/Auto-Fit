# 기획 핵심 요약

본 문서는 Auto Fit의 서비스 기획, 데이터 활용 구조, AI·분석 기능, 시스템 구현 현황, 성능 검증 계획과 팀 수행 체계를 설명하기 위한 외부 배포용 기획서다. 구현 수치와 검증 결과는 2026년 9월 22일 (기존 측정·설계 기준) 기준이며, 목표 지표와 실측 결과를 구분해 제시한다.

**문제** 건강검진과 체성분 결과는 숫자로 제공되지만, 사용자가 오늘 무엇을 먹고 어떤 운동을 해야 하는지까지 연결해 주지 못한다.

**해결** OCR로 데이터를 구조화하고 사용자가 확인한 확정값에 규칙 기반 안전 판정을 적용한 뒤, 식단·운동 추천과 행동 기록·재조정을 하나의 흐름으로 제공한다.

**차별점** 추천을 한 번 생성하는 데서 끝나지 않고 계획 적합성, 불편·미수행 기록, 한 끼 재추천, 운동 세션 조정을 다음 행동에 반영한다.

**현재 근거** public 44개 테이블, OpenAPI 45개 경로·57개 작업, 운동 180개·질환/상태 9종·조합 규칙 1,620건, OCR 합성 데이터 98장 중간 검증이 정리돼 있다.

**주의** DB와 API의 존재는 운영 배포나 AI 성능 달성을 의미하지 않는다. 푸드샷·추천 적합성·RAG는 아직 실측 결과가 없다.

# 1 주제와 서비스 정의

## 1.1 프로젝트 주제

Auto Fit은 일반 사용자의 체중 관리와 식단·운동 병행을 기본 대상으로 하되, 건강검진·체성분·알레르기·질환 및 주의 정보를 선택적으로 반영하는 웰니스 기반 개인 건강관리 서비스다. 당뇨 전용 서비스가 아니며, 질환 정보는 추천 안전성을 높이는 건강 고려 모드로 사용한다.

## 1.2 핵심 사용자

| **사용자**              | **필요**                         | **Auto Fit 제공 가치**                     |
|-------------------------|----------------------------------|--------------------------------------------|
| 다이어트 사용자         | 체중보다 체지방·근육을 함께 관리 | 체성분 기반 감량 전략과 식단·근력 연계     |
| 식단·운동 병행 사용자   | 서로 충돌하지 않는 통합 계획     | 하루 목표와 수행 기록을 함께 반영          |
| 건강 수치가 있는 사용자 | 결과지를 행동으로 해석           | OCR 확인 후 주의 조건과 대안 표시          |
| 노년층·초보자           | 복잡하지 않고 안전한 안내        | 핵심 문장 우선, 상세 펼쳐보기, 난이도 조정 |

## 1.3 제공 범위

- 건강검진·체성분 업로드, OCR 확인·수정·확정

- 건강 상태 요약과 계획 적합성 점검

- 맞춤 식단 추천, 한 끼 재추천, 섭취 기록

- 맞춤 운동 루틴, 세션 수행, 불편·난이도 피드백

- 주간·월간 변화 리포트와 챗봇 설명

의료 진단, 치료 지시, 질병 확정, 음식 중량 완전자동 확정, 실시간 자세 분석은 이번 MVP에서 제외한다.

# 3 제안 내용과 핵심 흐름

| **단계** | **사용자 행동**                 | **시스템 처리**                     | **결과**                   |
|----------|---------------------------------|-------------------------------------|----------------------------|
| 1 입력   | 프로필·목표 입력, 결과지 업로드 | 인증, 파일 저장, OCR 요청           | 원본과 추출값              |
| 2 검수   | 저신뢰·누락값 확인과 수정       | 단위·범위·문서유형 검증             | 확정 건강 데이터           |
| 3 분석   | 분석 결과 확인                  | 규칙 계산, 안전 조건, 근거 연결     | 핵심 요약·주의·목표        |
| 4 추천   | 식단·운동 조건 선택             | 금기 제거, 적합도 순위화, 설명 생성 | 하루 식단·운동 루틴        |
| 5 수행   | 섭취·운동·불편·난이도 기록      | 세션·로그·피드백 저장               | 완료율·대체안              |
| 6 재조정 | 다음 계획 확인                  | 미수행과 실제 기록 반영             | 한 끼 재추천·Plan B·리포트 |

## 3.1 화면 범위와 표시 원칙

- Upload → OCR Result → Total Analysis → Diet/Exercise → 기록·리포트 → AI Chat 흐름을 유지한다.

- 분석 결과는 핵심 2~3문장을 우선 노출하고, 상세 근거와 수치는 펼쳐보기로 제공한다.

- 카드 제목과 요약은 짧게 유지하고 긴 설명은 말줄임 후 상세 화면에서 확인한다.

- 사용자가 음식명·섭취량·운동 난이도·장비·컨디션을 수정할 수 있게 한다.

- BMR, 중성지방, 허리둘레, HDL 등 확장 지표는 화면과 판단 규칙이 승인된 항목만 노출한다.

# 4 데이터와 AI 적용 설계

| **기능**  | **입력**                                | **판단 주체**                           | **출력**                            |
|-----------|-----------------------------------------|-----------------------------------------|-------------------------------------|
| OCR       | 건강검진·체성분 파일                    | CLOVA General + 항목 파서 + 사용자 검수 | 건강검진 24개 또는 체성분 26개 필드 |
| 건강 분석 | 확정 건강값, 목표, 생활조건             | 서버 계산·규칙 엔진                     | 요약, 주의조건, 목표와 분석 스냅샷  |
| 식단 추천 | 영양 목표, 알레르기, 재료, 섭취 이력    | rules_v1 + 검증된 식품 DB               | 끼니, 음식, 양, 영양값, 대체안      |
| 운동 추천 | 목표, 수준, 시간, 장소, 장비, 건강 조건 | 금기 필터 + rules_v1 + 운동 DB          | 루틴, 세트, 반복, 시간, 주의사항    |
| 근거·설명 | 판정 결과와 승인 문서                   | RAG 검색 + LLM 설명                     | 이유, 제외 사유, 대안, 출처         |
| 리포트    | 체성분 변화, 섭취·운동·피드백 로그      | 기간 집계 + 요약                        | 달성률, 변화, 다음 행동             |

## 4.1 안전 설계

- LLM은 건강 판정과 수치 계산을 직접 수행하지 않고, 확정된 결과를 설명한다.

- 질환·부상 금기 규칙은 추천 점수와 생성 문장보다 먼저 적용한다.

- OCR 미확정값과 신뢰도 0.5 미만 값은 분석 입력으로 사용하지 않는다.

- 결과에는 적합·조정 권장·전문가 확인 권고 등급과 이유·대안·비진단 안내를 제공한다.

- 입력 부족, API 장애, 지원하지 않는 문서는 직접 입력과 텍스트 정보로 폴백한다.

# 5 현재 구현 구조

**API** FastAPI /api/\* 기준 7개 OpenAPI 태그, 45개 경로, 57개 작업이 정리돼 있다. GET /health를 제외하면 Supabase access token이 필요하고 사용자 ID는 서버가 토큰에서 결정한다.

| **영역**       | **작업 수** | **핵심 구현 범위**                                   |
|----------------|-------------|------------------------------------------------------|
| 시스템         | 2           | 상태 확인, 인증·DB 왕복 검사                         |
| 프로필         | 7           | 홈, 프로필, 알레르기, 온보딩, 계정 삭제              |
| 건강 문서·분석 | 8           | 업로드, OCR 수정·확정, 최신 분석·팝업 조회           |
| 운동           | 20          | 설정, 추천, 세션, 불편, 피드백, 목표, 이력·추이      |
| 식단           | 13          | 재고, 추천, 재추천, 영양 요약, 식사 사진·피드백·이력 |
| 챗봇           | 7           | 대화, 메시지, 미리보기, 재전송·호출 제한             |

## 6.1 관계와 무결성

현재 구조는 물리적 FOREIGN KEY를 전면 적용하지 않고, 논리적 참조 필드와 DB 트리거로 주요 사용자·업무 참조와 운동 세션 소속을 검사한다. 이는 삭제 연쇄를 피하려는 설계 선택이지만, 애플리케이션과 트리거에서 무결성 검증을 지속해야 한다.

ERD에 disease_risk 관련 테이블이 존재하지만 질병 위험 예측은 이번 MVP 사용자 기능에서 제외한다. 확장용 스키마와 현재 제공 기능은 문서와 서비스 화면에서 명확히 구분한다.

## 7.1 목표 KPI

| **KPI**               | **목표**                                                       | **평가 방법**                                |
|-----------------------|----------------------------------------------------------------|----------------------------------------------|

## 15.2 건강 문서 OCR 및 확정

지원 대상으로 논의된 자료는 건강검진 결과지와 체성분 결과지이며, 업로드 형식은 PDF·JPG·PNG 등을 포함한다. 기존 외부 배포용 문서에는 건강검진 24개, 체성분 26개 필드가 기재되어 있다. 이는 당시 추출 설계 범위이며 최신 OCR 서버 응답 필드의 확정 목록으로 오인하지 않는다.

| 세부 기능   | 기획 동작                                 | 오류·예외 처리                             |
|-------------|-------------------------------------------|--------------------------------------------|
| 문서 업로드 | 파일 선택→형식·용량 검증→OCR 처리         | 미지원 형식, 손상 파일, 네트워크 장애 안내 |
| OCR 검수    | 추출값·단위·신뢰도 확인, 사용자 직접 수정 | 누락값 null 유지, 자동 추정 금지           |
| 확정 처리   | 사용자가 수정·확인한 수치만 분석에 반영   | 미확정 문서·충돌 데이터 구분               |
| 문서 삭제   | 업로드 파일과 연계 데이터 삭제 요청       | 원본·파생값·스토리지 처리 결과 확인        |

9월 22일 문서의 합성 결과지 98장 문서 판별 98/98, OCR 오탐률 1.6%, 누락률 10.4%, 숫자 완전일치율 88.2%, 항목 탐지 F1 93.0%, 서버 경유 평균 3.9초는 당시 중간 평가로만 인용한다. 실제 사용자 촬영·PDF 평가 결과는 추가 검증 전까지 미확인이다.

## 15.3 건강 상태 통합 분석

- 입력: 확정된 키·체중·BMI·체지방률·골격근량·혈압·혈당·지질 관련 값 등 문서에서 확보된 항목.

- 처리: 서버 계산 및 승인된 규칙으로 주요 지표를 평가하고, 식단·운동 계획에 필요한 주의 조건을 구조화한다.

- 출력: 핵심 요약 2~3문장, 주요 관리 항목, 상세 근거와 주의사항을 단계적으로 제시한다.

- 표시: 기존 key_metric_keys 등 핵심 지표 중심으로 노출하고 보조 지표의 확장 여부는 화면 승인 후 결정한다.

- 안전: 위험 예측 또는 질병 확정처럼 읽히는 표현은 배제하고 전문가 상담 권고가 필요한 경우 별도 안내한다.

## 15.4 식단 추천·한 끼 재추천·섭취 기록

식단 추천은 확정 건강 데이터, 건강 목표, 알레르기, 음식·영양 데이터 및 섭취 이력 등을 고려한다. 기존 9월 기획서의 하루 식단·한 끼 재추천 흐름을 유지한다. 10월 19일 개발 공유 문서에서는 7일 × 하루 4끼 = 총 28개 식사 슬롯의 주간 식단 구조가 언급되었으나, 당시 백엔드 로컬 구현 검증과 실제 AI 서버·프론트엔드 통합 완료는 구별해야 한다.

| 기능         | 기대 출력                                       | 검증 포인트                         |
|--------------|-------------------------------------------------|-------------------------------------|
| 추천 생성    | 식사 구분, 메뉴, 권장량, 열량·영양소, 추천 이유 | 영양정보 DB 근거 및 알레르기 필터   |
| 주간 계획    | 7일 × 4끼 = 28개 슬롯 구조(10월 개발 자료)      | 실제 AI 응답·화면 렌더링 E2E 미확인 |
| 한 끼 재추천 | 선택 끼니의 대체 메뉴·변경 사유                 | 다른 끼니 유지 여부, 응답 누락 필드 |
| 섭취 기록    | 실제 섭취·수정 내역과 요약                      | 추천값과 실제 섭취값 분리           |
| 푸드샷       | 사진 기반 음식 후보와 영양정보 연결             | 음식명 수정, 중량 자동 확정 금지    |

푸드샷 정확도 90%는 목표이며, 외부 API 계약 및 실측 결과가 확보되지 않은 상태에서는 달성 또는 상용 연동 완료로 표기하지 않는다. 음식 사진은 판별 보조 수단이며 섭취량을 사용자 확인 없이 확정하지 않는다.

## 15.5 운동 추천·수행·영상

기존 자료에는 운동 180개, 건강 상태 9종, 조합 규칙 1,620건의 내부 구축 기준이 제시되어 있다. 이 수치는 운동 추천 정확도나 실제 운영 DB 적재 건수와 동일하지 않다. 운동 추천 시 목표, 수준, 시간, 장소, 장비, 건강·불편 조건을 고려하며 금기 필터를 추천 순위보다 먼저 적용한다.

- 추천 루틴: 운동명, 수행 방법, 세트·반복·시간, 주의사항, 대체 운동 정보를 제공하는 방향으로 설계한다.

- 운동 세션: 시작→운동별 수행→완료→불편·난이도 피드백→다음 계획 반영 흐름을 기준으로 한다.

- 운동 영상: MuscleWiki 등 외부 공급자 검토 이력이 있으나 최종 계약·요금·한국어 설명 검수 여부는 확인이 필요하다.

- 운동 영상 UI는 기존 논의의 무음 자동 반복 및 210~230px 높이 원칙을 참고하되, 실제 구현 여부는 화면 점검 대상이다.

- 운동 중 통증·불편 보고 시 안전한 대체안 또는 중단 안내를 우선하고, 의료적 진단 문구는 제공하지 않는다.

# 17 데이터·AI·시스템 구성 상세

## 17.1 데이터 계층

- 개인 입력: 사용자 프로필, 목표, 동의, 확정 건강 수치, 식사·운동 수행 로그.

- 문서 계층: 건강검진·체성분 원본 파일, OCR 추출 결과, 사용자 수정·확정 기록.

## 18.2 테스트 시나리오

- 정상 흐름: 회원가입→문서 업로드→OCR 검수→건강 분석→식단·운동 추천→수행 기록→리포트.

- OCR 예외: 흐린 사진, 다중 페이지 PDF, 수치 누락, 단위 오인식, 지원하지 않는 문서, 취소 및 삭제.

- 추천 예외: 알레르기, 건강 주의 조건, 식품 DB 누락, 운동 금기 충돌, 후보 없음.

- API 예외: 인증 만료, 권한 위반, 중복 요청, 외부 AI 서버 지연·503, 재시도 후 중복 생성 방지.

- 커뮤니티 예외: 신고 후 숨김, 차단 관계, 개인정보 포함 게시물, 회원 탈퇴 중 동시 요청.

- 러닝 예외: 위치 권한 거부, 지도 API 실패, 경로 거리 오차, 유효하지 않은 좌표.

## 18.3 개인정보 처리와 건강정보 안내

건강검진표와 체성분 결과에는 민감한 건강정보가 포함될 수 있으므로 수집 목적·항목·보관·삭제·외부 OCR 전송 여부를 사용자에게 명확히 안내해야 한다. 회원가입 시 포괄 동의 한 번으로 모든 건강정보 처리가 적법해진다고 단정할 수 없다. 실제 처리 방식, 동의 문구, 위탁·제3자 제공, 저장·삭제 정책은 운영 전 별도 법률·보안 검토가 필요하다.
