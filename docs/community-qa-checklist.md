# 커뮤니티 실서버 점검표

기준일: 2026-10-21. `community-backend`·`community-frontend`를 팀 브랜치에 병합하고 Render에 배포한 뒤,
실제 앱(Expo Go 또는 빌드)에서 사람이 직접 눌러 보는 순서다. 로컬 시험(PGlite·pytest)으로 확인할 수 없는 것,
즉 실제 Supabase·Storage·Render·휴대폰에서만 드러나는 문제를 찾는 것이 목적이다.

## 0. 준비

| 항목 | 내용 |
| --- | --- |
| 계정 | 시험 계정 2개(A, B, 닉네임 있음) + 운영자 계정 1개(M, `community_moderators`에 등록된 계정) |
| 기기 | 휴대폰 1대 이상(아이폰이 있으면 아이폰 포함), 나머지는 웹이나 다른 휴대폰 |
| DB 버전 | `list_migrations`에 아래가 모두 있어야 한다. 하나라도 없으면 해당 기능 API가 502를 낸다 |
| 서버 | `GET https://auto-fit-api-dev.onrender.com/health` 200, 로그인 없이 `/api/community/feed`·`/api/community/conversations`·`/api/community/admin/rules`가 401 |

필요한 원격 버전: `20261014062855_community_feed`, `20261015005534_community_comment_delete_lock_order`,
`20261015014915_community_follows_notifications`, `20261015062629_community_mileage_membership_clubs`,
`20261015064753_community_challenges_rankings`, `20261019022924_community_club_management`,
`20261019022935_community_moderation`, `20261019023132_community_direct_messages`,
운영자 도구(`20261023002812_community_admin_tools`, 저장소 파일 `20261019130000_community_admin_tools.sql`).

시험 데이터는 다른 팀원에게도 보인다. 글·댓글 내용 앞에 `[시험]`을 붙이고, 끝나면 7절대로 지운다.

## 7. 정리(꼭 하기)

1. A·B가 쓴 `[시험]` 글·댓글을 삭제하고, 만든 클럽을 삭제한다(클럽 글과 사진이 함께 지워진다).
2. 시험용 챌린지는 운영자 도구에서 끈다(지우는 기능은 없음).
3. 바꾼 마일리지 규칙이 시험값이면 팀이 정한 값으로 되돌린다.
4. 시험 계정을 지울 때는 앱의 회원 탈퇴를 쓴다. 커뮤니티 데이터·사진·대화가 함께 지워지는지 다른 계정에서 확인한다.

## 문제가 생기면

- 화면에 나온 오류 문구, 시각, 계정(이메일 말고 닉네임), 기기 종류를 적는다.
- 502 `DATA_SOURCE_ERROR`가 특정 기능에서만 나면 그 기능의 SQL이 적용됐는지(0절 버전 목록)부터 본다.
- 사진 업로드 415는 HEIC 같은 지원하지 않는 형식이다(JPEG·PNG·WebP만). 앱은 HEIC를 미리 빼지만, 다른 형식이면 알려 준다.
