# 챗봇 기능 확장

2026-11-02 작업본. 백엔드의 기존 인증·소유권 검사를 재사용한다. 배포 전 실환경 연동은 별도 검증한다.

## 조회와 추천

- `풍암동 런닝코스를 알려줘`처럼 지역이 포함된 질문은 러닝 코스 검색으로 보낸다. AI 코스 서버가 사용 가능하면 그 검색 결과를, 그렇지 않으면 활성 `running_courses` 카탈로그를 조회한다. 둘 다 결과가 없으면 코스를 지어내지 않고 러닝 화면을 안내한다. 지역이 없으면 지역명을 묻고 다음 메시지의 지역 답변을 이어받는다.
- 러닝 기록·저장 코스·페이스, 운동 기록·진행·목표·추천, 식사 기록·식단·영양·보유 재료, 건강 기록·문서·분석, 프로필·알레르기·설정·마일리지·티어는 인증된 기존 GET API로 조회한다. 모델이 임의의 API 경로를 선택하지 못하도록 서버에 조회 경로를 고정했다.
- 기존의 운동 루틴 생성은 유지한다. 러닝 코스의 실제 지도 경로 생성, GPS 추적, 파일 업로드, 커뮤니티 작성 등 화면 입력이 필요한 기능은 해당 화면으로 이동해 이어서 사용한다.
- 일반 정보 질문의 채팅방당 1회 제한을 제거했다. 모델을 사용할 수 없으면 일시적으로 이용할 수 없다고 안내한다. 기존 60초 요청 한도는 유지한다.

## 채팅 응답의 화면 이동

`evidence`에 `{ "type": "navigation", "route": "/exercise/running", "label": "러닝 화면 열기" }` 형식의 항목을 넣는다. 앱은 허용된 내부 경로만 버튼으로 표시한다. 경로 문자열을 모델이나 사용자 메시지에서 직접 받지 않는다.

## 기록 수정·삭제

1. 사용자가 냉장고 재료나 건강 문서 목록을 조회한다. 최대 5개 항목을 번호로 표시한다.
2. `1번 삭제해줘` 또는 냉장고 재료에 `1번 수량을 3으로 수정해줘`라고 요청한다.
3. 챗봇은 대상·변경 내용·삭제 영향을 보여 주고 `확인` 또는 `취소`를 기다린다. 미리보기는 변경을 실행하지 않는다.
4. 같은 채팅방에서 10분 안에 확인하면 기존 소유권 검사 API로 실행한다. 저장한 기록 참조가 없거나 시간이 지나면 다시 조회하도록 안내한다.

건강 문서 삭제는 원본 파일과 연결된 검진·체성분 및 파생 분석 자료에도 영향을 준다는 문구를 표시한다. 계정 삭제는 채팅에서 실행하지 않는다. 임의의 URL·HTTP 메서드·사용자 ID를 모델 또는 클라이언트가 지정할 수 없다.

## 운영 확인

- 배포 환경의 `AI_SERVER_ENABLED`, `AI_SERVER_BASE_URL`, `AI_SERVER_API_KEY`와 활성 코스 데이터가 있어야 실제 코스 검색 결과를 보여줄 수 있다. 비활성 상태에서도 챗봇은 해당 질문을 서비스 외 질문으로 차단하지 않는다.
- 백엔드와 프론트엔드는 서로 다른 작업본에 있으므로 두 변경이 함께 배포되어야 화면 이동·확인 버튼까지 보인다.
- 챗봇 단위 검사와 앱 TypeScript 검사는 통과했다. 운영 데이터에 대한 생성·수정·삭제 검사는 수행하지 않았다.
