## 5. Backend 반영 요청

1. 두 `exercise_key`와 실제 제공하는 GIF의 `asset_id`를 대조합니다. 이름 유사도만으로 연결하지 않습니다.
2. 기존 제외 목록을 우선 적용하고, 위 자산과 일치하는 두 키의 `method → caution → focus` 세 문장과 검토 상태를 안내 저장 구조에 반영합니다.
3. 두 키의 이전 문장·음성·앱 캐시를 갱신합니다. 검토 꼬리문구와 JSON의 내부 `review_note`는 음성으로 읽지 않습니다.
4. 이미 기존 교정본을 반영했다면 두 키만 추가 적용합니다. 처음 적용한다면 현재 JSON의 3,082키를 기준으로 기존 인계 절차를 수행합니다.
5. 두 키의 매칭·저장 결과, 사용한 자산, 음성 캐시 갱신 결과와 앱 재생 여부를 회신해 주세요.

현재 흐름은 `recommendation_router → exercise_recommendation_service → CSV 후보 / RAG / OpenAI → ExerciseItem`입니다. 추천 응답의 `instructions`는 이번 안내 JSON을 자동으로 읽지 않습니다. AI 서버를 배포하는 것만으로 운영 음성이 바뀌지는 않으며, 기존 안내 데이터에 대한 반영이 필요합니다.

요청·응답 API, 카탈로그, 저장된 운동 기록 및 완료 분석 문장을 변경하는 작업은 아닙니다. 미매칭·보류 항목을 LLM 문장이나 이전 음성으로 우회하지 않는 기존 정책도 유지합니다.
