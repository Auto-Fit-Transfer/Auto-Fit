# Auto-Fit 표준 건강항목표 (v1.0)

작성: 이승현 (AI/데이터) · 2026-08-31

## 이 문서는 무엇인가

OCR이 건강문서에서 **뽑아낼 항목의 공식 목록**입니다.
아래 세 곳이 전부 이 목록의 `key`와 `unit`(단위)을 그대로 씁니다.

| 쓰는 곳 | 담당 | 어떻게 쓰는가 |
|---|---|---|
| OCR 파서 | 이승현 | 이 `anchors`(문서에 인쇄된 항목명)를 기준점으로 숫자를 집는다 |
| DB 테이블 설계 | 김현호 | 컬럼명 = `key`, 자료형 = `type` |
| 건강분석 규칙 | 이승현 → 이병희 | 이 `key`로 판정하고, 판정 결과를 LLM이 설명한다 |

**규칙 하나:** 항목을 추가하거나 이름을 바꿀 때는 `health_fields.json`을 먼저 고치고 팀에 공유합니다.
각자 코드에 항목명을 직접 적어 넣으면 나중에 반드시 어긋납니다.

## 우선순위

전체 50개 항목.

| 등급 | 뜻 | 개수 |
|---|---|---|
| **P1** | 필수. 건강분석·식단·운동 추천이 이 값 없이는 동작하지 않음 | 17 |
| **P2** | 권장. 분석 품질을 높이는 보조 항목 | 18 |
| **P3** | 참고. 화면 표시용, 실패해도 서비스 진행 가능 | 15 |

정확도 개선은 **P1부터** 합니다. P3 항목이 90%든 60%든 서비스 품질에 영향이 없습니다.

## 파싱할 때 주의할 항목 4개

1. **혈압** — `129/77`처럼 한 칸에 인쇄됩니다. 슬래시로 나눠 `sbp`/`dbp` 두 값으로 저장합니다.
2. **체중조절/지방조절** — 음수(`-4.7`)가 나옵니다. 마이너스 기호를 놓치면 감량이 증량으로 뒤집힙니다.
3. **BMI** — 문서에 인쇄된 값과, `weight ÷ (height/100)²`로 직접 계산한 값을 비교합니다. 차이가 0.5를 넘으면 셋 중 하나를 잘못 읽은 것이므로 전부 `review` 처리합니다.
4. **처방 의약품** — 여러 줄짜리 표라서 다른 항목과 파싱 방식이 완전히 다릅니다. P1 항목이 안정된 뒤에 손댑니다.

## OCR 결과 반환 형식

값만 돌려주지 않고 **신뢰도와 상태를 함께** 돌려줍니다. 기획서의 "추출 결과 확인·수정 후 저장" 화면이 이 상태값으로 동작합니다.

```json
"smm": { "value": 35.7, "confidence": 0.61, "status": "review", "raw_text": "35.7" }
```

| status | 조건 | 화면 동작 |
|---|---|---|
| `ok` | 신뢰도 0.85 이상 + 유효범위 통과 | 자동 저장 |
| `review` | 신뢰도 0.5–0.85 또는 값이 의심스러움 | 해당 칸을 강조해 사용자 확인 요청 |
| `fail` | 추출 실패 또는 유효범위 밖 | 사용자가 직접 입력 |

## 정답지 대조 방법

합성 데이터 `labels/<구간>/P####.json`이 정답입니다.
각 항목의 `label_path`가 정답지 안의 위치를 가리킵니다.

예: `smm`의 `label_path`는 `inbody.smm` → 정답지의 `["inbody"]["smm"]` 값과 비교

숫자 항목은 **소수점 자리 기준 완전일치**로 채점합니다 (35.7 vs 35.8 = 오답).
반올림 오차를 봐주기 시작하면 실제 정확도를 알 수 없게 됩니다.
